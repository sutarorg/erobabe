## Remaining risks / incomplete acceptance

1. **BLOCKED:** no authorized provider/staging credentials or account approvals. No genuine upload, payment, IPN delivery, email, RLS-over-PostgREST, or backup restoration verified. PGlite uses real application SQL with Supabase auth/storage infrastructure fixtures; it is not staging or independent concurrent connections.
2. **FAIL:** npm audit retains five high findings in `eslint-config-next → @next/eslint-plugin-next → fast-glob → micromatch → braces@3.0.3`, one advisory: [GHSA-vfj7-8cjw-p6xm](https://github.com/advisories/GHSA-vfj7-8cjw-p6xm). No patched braces version was available from the registry at inspection; current Next ESLint plugin still uses this chain. Obtain compatible patched tooling or documented approved tooling-only risk disposition. Do not blindly force a framework downgrade.
3. **BLOCKED:** content rights, consent/adult-performer records, real operator identity, jurisdiction-specific age assurance, removal operations, privacy policy, hosting-plan adult-content approval and each provider's business/content approval. Self-declared age is not verified age.
4. **NOT TESTED:** authenticated desktop/mobile page content and all controls with real admin/two advertiser accounts; PKCE email verification/recovery/session expiration; genuine multi-file interruption/resumption; provider amount/refund/expiration scenarios; new recovery/operator RPCs over deployed Supabase; load and failure recovery across processes.
5. **BLOCKED:** trusted ingress overwriting x-real-ip, bot/WAF policy, daily pruning schedule, production alerting, DNS/HTTPS, sender verification, backup restore, incident response and staffed reconciliation. Client visibility events are spoofable; daily hashes and rate budgets reduce abuse, not certify impressions. Historical campaign counters have no retroactive verified event evidence.
6. **Policy/code follow-up:** pending creative objects remain addressable by exact URL in the existing public bucket. Private premoderation storage and byte-level creative scanning require implementation if operator/content policy requires them. Rejected-creative replacement and a full support-agent reply/close UI remain unfinished; current support tickets are persisted/readable and support email is optional. These limitations must be resolved or explicitly accepted for the controlled pilot.
7. **Operational follow-up:** expiry releases inventory logically; uncertain payment invoices stay pending until reconciliation. Late settlement after hold expiry records receipt but does not auto-deliver. Review historical overlaps/approvals before migration, monitor stale pending records, and document refund/rebooking decisions. Twenty-four-hour previously issued Bunny TUS signatures are not instantly revoked by app suspension; provider/key revocation is required for emergencies.

## Evidence interpretation

Existing tests were not removed/skipped. Changed expectations reflect explicit behavior corrections: uncertain provider creation now preserves pre-provider claims; encoded video waits for review; admin sign-in is `/admin/signin`; an empty sitemap is valid. Populated sitemap fixtures and missing-video HTTP status assertions remain explicit. External acceptance and security review are release gates even when every local command passes.

### Final request-boundary correction

A final review found middleware previously checked session identity but left current role/suspension to layouts. Layouts can stay mounted across client/RSC navigation while service-backed pages query independently. Middleware now rechecks profile role/status on **every protected request**, fails closed on missing/failed profile reads, routes active admins to their own portal, and preserves refreshed session cookies on redirects. Ten new route-boundary regressions pass; final full suite: **47 files / 536 tests**. Private pending-review video rows also no longer offer public watch links that necessarily 404. Genuine authenticated staging verification remains required.


### October 15 continuation: payment recovery and settlement corrections

Additional review found malformed positive-amount evidence was not checked before recovery permanently bound a quote; recovery lacked an actor audit and treated identical raced retries as failures. A shared checkout/recovery quote validator and forward-only migration **18 payment_recovery** now enforce bounded positive decimal quotes, exact order/asset/USD-price identity, active-admin attribution, immutable row-locked binding, and atomic audit/event persistence. Existing migrations are unchanged.

A second defect occurred when a finished notification disagreed with the subsequently fetched provider state: a standalone payment update could write a terminal status without its invoice/campaign effects. That path now returns a retry without changing payment state; normal settlement handles all effects together on current evidence. The settlement caller also still used a legacy 2% default tolerance; it now explicitly uses zero tolerance so near-miss under/overpayments remain in reconciliation. A controlled run of the prior verifier against five new cases reproduced **five failures**, then the repaired code passed. The filtered reproduction is diagnostic, not the full acceptance suite.

New recovery-route coverage uses the real authorization/helper/verifier with provider and DB boundaries mocked, including absence of privileges, malformed/missing identity, replay, unknown funds, near-miss amounts, refund, provider drift and settlement failure/retry. New full-migration SQL cases independently test RPC grants, active-admin enforcement, malformed amounts, immutable retries, actor auditing and rollback when the audit insert fails. Sequential local retries do **not** prove independent-session concurrency.

The October 15 npm registry/advisory recheck still reports **five high tooling findings**; available braces remains 3.0.3 and the latest Next ESLint plugin still declares the affected chain. No dependency risk was waived. Production-only audit remains zero. Genuine staging, policy, unfinished support/creative UI and operational release gates are unchanged.
